# Security — GRUB2 Theme Nuci

Security considerations for the theme package and its deployment.

## Threat Model

### Assets Protected
- Boot integrity (prevent unauthorised boot modification)
- Theme asset integrity (prevent malicious asset substitution)
- GRUB2 parser safety (prevent exploitation via malformed assets)

### Threat Actors
- Local attacker with root access (can modify theme files)
- Supply chain attacker (compromised upstream assets)
- Physical attacker (modify boot media)

### Out of Scope
- GRUB2 upstream vulnerabilities
- Firmware/BIOS/UEFI vulnerabilities
- Kernel/initramfs vulnerabilities
- OS-level security

## Theme Security Properties

### No Executable Code
- Theme contains only: PNG images, text descriptor
- No scripts, binaries, or interpreted code
- No attack surface from theme execution

### No Network Access
- Theme loaded from local filesystem only
- No HTTP, FTP, or other network protocols
- No telemetry, no phoning home

### No Data Collection
- Theme does not read, write, or transmit data
- No user tracking, no analytics
- See [PRIVACY.md](../PRIVACY.md)

## Asset Integrity

### Supply Chain Risks

| Risk | Mitigation |
|------|------------|
| Malicious PNG | Verify PNG validity; no embedded scripts |
| Compromised icon | Review icon sources; manual audit |
| Modified theme.txt | Git history review; signed commits |

### PNG Safety

GRUB2's PNG decoder (`grub-core/fs/png.c`):
- Parses PNG chunks sequentially
- Validates CRC32 per chunk
- Limits: no explicit size limits in decoder
- Risk: Large PNG could cause OOM

**Mitigation:**
- Keep assets small (< 500 KB background, < 50 KB icons)
- Verify with `file` command before install
- Monitor GRUB2 security advisories

### Theme Descriptor Safety

`theme.txt` parsed by GRUB2 theme engine:
- Simple key-value and block parser
- No complex parsing (no regex, no recursion)
- Risk: Buffer overflow in parser (upstream concern)

**Mitigation:**
- Keep theme.txt simple
- Test with target GRUB2 version
- Monitor GRUB2 security advisories

## Installation Security

### File Permissions

```bash
# Correct permissions (enforced by install procedure)
find /usr/share/grub/themes/Nuci -type d -exec chmod 755 {} \;
find /usr/share/grub/themes/Nuci -type f -exec chmod 644 {} \;
```

**Rationale:**
- Directories: 755 (read/execute for all, write for root)
- Files: 644 (read for all, write for root)
- Prevents unauthorised modification

### Path Security

- Theme installed to `/usr/share/grub/themes/Nuci/` (root-owned)
- `GRUB_THEME` points to absolute path
- No relative paths, no symlinks in theme.txt

### GRUB Configuration

```bash
# GRUB_THEME set in /etc/default/grub (root-only write)
GRUB_THEME=/usr/share/grub/themes/Nuci/theme.txt

# grub.cfg generated by root
sudo grub-mkconfig -o /boot/grub/grub.cfg
```

## Secure Boot Considerations

### Theme Not Signed

- Theme assets not signed by Secure Boot keys
- GRUB2 loads theme before kernel verification
- Malicious theme could exploit GRUB2 parser

### Mitigations

1. **Trusted source only:** Install from official repository or verified AUR package
2. **Verify assets:** Run verification scripts before install
3. **Monitor GRUB2:** Apply GRUB2 security updates promptly
4. **Physical security:** Protect boot media from modification

## Vulnerability Reporting

See [SECURITY.md](../SECURITY.md) for reporting process.

### In-Scope for This Theme

- Malicious asset in theme package
- Supply chain compromise of theme repository
- Theme descriptor causing GRUB2 crash

### Out-of-Scope

- GRUB2 parser vulnerabilities (report to GRUB2 upstream)
- Firmware vulnerabilities
- OS/kernel vulnerabilities

## Hardening Recommendations

### For Distributions Packaging This Theme

1. **Reproducible builds:** Ensure theme assets match source
2. **Signature verification:** Sign package with distribution key
3. **Integrity checks:** Include verification in package install
4. **Minimal permissions:** Install with root:root 755/644

### For End Users

1. **Verify download:** Check git commit signatures
2. **Run verification:** `./verify-assets.sh` before install
3. **Monitor updates:** Watch for security advisories
4. **Physical security:** Encrypt boot partition if possible

## Security Testing

### Pre-Release Checks

```bash
# 1. Asset validation
./verify-assets.sh

# 2. Contract verification
./verify-contracts.sh

# 3. PNG structure check
for f in Nuci/*.png Nuci/icons/*.png; do
  pngcheck -v "$f" 2>&1 | grep -E '(ERROR|WARNING)' && echo "ISSUE: $f"
done

# 4. Theme.txt syntax (basic)
# No formal validator; GRUB2 is the test
```

### Penetration Testing

Not applicable for static assets. Focus on:
- GRUB2 parser fuzzing (upstream responsibility)
- PNG decoder fuzzing (upstream responsibility)

## Incident Response

If malicious theme discovered:

1. **Revoke:** Remove compromised version from distribution
2. **Investigate:** Determine scope (assets, theme.txt, repo)
3. **Remediate:** Publish clean version with verified assets
4. **Notify:** Security advisory via GitHub Security Advisories
5. **Rotate:** If signing keys compromised, rotate keys
